# Network Protocol Analysis for Blue Teams

## TCP Analysis

TCP (Transmission Control Protocol) is the foundation of most application-layer communications. Understanding TCP behaviour is essential for detecting scanning, exploitation, and data transfer anomalies.

### TCP Flags and Their Security Implications

- **SYN**: Initiates a connection. A high volume of SYN packets to many ports on a single host indicates a SYN scan (port scan). A high volume of SYN packets to the same port across many hosts indicates a horizontal scan or worm propagation.
- **SYN-ACK**: Server response to a SYN, indicating an open port. Logging SYN-ACK responses can reveal which services are accessible.
- **RST (Reset)**: Abruptly terminates a connection. A flood of RST packets from a target indicates closed ports during a scan. Unexpected RST packets may indicate a TCP reset attack or firewall intervention.
- **FIN**: Graceful connection close. FIN scanning (sending FIN to closed ports, which respond with RST) is a stealthy scanning technique that bypasses some stateless firewalls.
- **PSH (Push)**: Requests immediate delivery of data to the application. Frequently seen in interactive sessions and data transfers.
- **URG (Urgent)**: Rarely used legitimately. Presence of URG flags can indicate evasion techniques or legacy exploit attempts.
- **XMAS Scan**: Packets with FIN, PSH, and URG flags set simultaneously. No legitimate application produces this combination. Detection is a strong indicator of reconnaissance activity.
- **NULL Scan**: Packets with no flags set. Like XMAS scans, this has no legitimate use and indicates reconnaissance.

### TCP Connection Analysis

A normal TCP connection follows the three-way handshake: SYN, SYN-ACK, ACK. Deviations from this pattern are significant:

- **Half-open connections**: SYN sent but no completing ACK after receiving SYN-ACK. Characteristic of SYN scanning (Nmap -sS).
- **Connections with no data transfer**: Full handshake followed by immediate FIN or RST. May indicate port knocking, connection testing, or scanner fingerprinting.
- **Retransmission storms**: Excessive retransmissions indicate network issues, but targeted retransmissions against a single service may indicate a denial-of-service attempt.
- **Window size anomalies**: Unusual TCP window sizes can fingerprint scanning tools. Nmap, Masscan, and other tools use distinctive window sizes.

### TCP Session Reconstruction

Reassembling TCP streams from individual packets reveals the complete application-layer conversation. This is critical for:

- Reconstructing HTTP requests and responses to find malicious downloads or data exfiltration.
- Recovering transferred files from SMB, FTP, or HTTP streams.
- Identifying command sequences in interactive sessions (SSH if keys are available, Telnet, unencrypted shells).

## UDP Analysis

UDP (User Datagram Protocol) is connectionless, making it harder to track sessions. Key security considerations include:

- **DNS traffic (port 53)**: The most common UDP protocol. Anomalous DNS traffic is covered in detail in `06_dns_analysis.md`.
- **DHCP (ports 67/68)**: Rogue DHCP servers can redirect client traffic. Look for DHCP responses from unexpected source IPs.
- **NTP (port 123)**: NTP amplification attacks use spoofed source addresses with monlist requests. NTP on non-standard ports may indicate C2 tunneling.
- **SNMP (port 161/162)**: SNMP with community strings "public" or "private" exposes device configuration. SNMPv1 and v2c transmit community strings in cleartext.
- **SSDP (port 1900)**: SSDP amplification attacks are common in DDoS scenarios.
- **Large UDP payloads**: Standard DNS queries are typically under 512 bytes (or 4096 with EDNS). UDP payloads significantly larger than expected for the protocol may indicate tunneling.

## ICMP Analysis

ICMP (Internet Control Message Protocol) is essential for network diagnostics but is frequently abused:

- **Type 8 (Echo Request) and Type 0 (Echo Reply)**: Standard ping. High-frequency pings or pings with oversized payloads may indicate ICMP tunneling for data exfiltration or C2 communication.
- **Type 3 (Destination Unreachable)**: Large volumes indicate scanning activity. Code 3 (Port Unreachable) responses map which UDP ports are closed.
- **Type 11 (Time Exceeded)**: Generated by traceroute. Used for network mapping reconnaissance.
- **Payload analysis**: Legitimate ICMP echo payloads contain padding bytes (typically repeating ASCII patterns). Non-standard ICMP payloads may contain encoded data, shell commands, or exfiltrated information. Tools like icmpsh and ICMPTunnel embed data in ICMP payloads.
- **ICMP redirect (Type 5)**: Can be used to manipulate routing tables. Should be blocked or closely monitored in most environments.

## Protocol Anomalies Indicating Attacks

### Protocol Misuse on Non-Standard Ports

Attackers frequently use standard protocols on non-standard ports to evade detection:

- **HTTP on non-80/443 ports**: C2 frameworks commonly use HTTP on high ports (8080, 8443, 8888, 4444). Detect by looking for HTTP request patterns (GET, POST, HTTP/1.1 headers) in traffic on unexpected ports.
- **DNS on non-53 ports**: DNS traffic on any port other than 53 is suspicious. Some C2 frameworks tunnel DNS-like queries over arbitrary ports. Detect by inspecting packet payloads for DNS query structure.
- **SSH on non-22 ports**: May be legitimate (administrators changing the default port) or may indicate tunneling. Detect by looking for the SSH protocol banner string.
- **SMB on non-445 ports**: SMB over non-standard ports may indicate lateral movement tools or relay attacks.
- **TLS on unexpected ports**: C2 frameworks use TLS on arbitrary ports. Certificate analysis and JA3 fingerprinting can identify these connections.

### Protocol Stack Violations

- **IP fragmentation abuse**: Overlapping fragments, tiny fragments, or excessive fragmentation can be used to evade IDS/IPS. Modern systems should reassemble fragments before inspection.
- **TTL anomalies**: Packets with TTL values of 1 may indicate traceroute-style reconnaissance. Inconsistent TTL values from the same source may indicate spoofing or man-in-the-middle activity.
- **IP options abuse**: Rarely used IP options (Source Routing, Record Route) can indicate reconnaissance or routing manipulation attempts.

## Layer 2 Analysis

When PCAP captures include Ethernet frames (link-layer type 1), Layer 2 analysis can reveal:

- **ARP spoofing**: Multiple IP addresses associated with the same MAC address, or a single IP address associated with multiple MAC addresses, indicate ARP spoofing or ARP cache poisoning. This is a prerequisite for man-in-the-middle attacks.
- **MAC flooding**: An extremely high number of unique source MAC addresses in a short period may indicate a CAM table overflow attack against network switches.
- **VLAN hopping**: 802.1Q tags in frames from hosts that should not be performing VLAN tagging may indicate VLAN hopping attempts.
- **Broadcast storms**: Excessive broadcast traffic may indicate a network loop or deliberate denial-of-service.

## Layer 3 Analysis

- **IP spoofing**: Source IP addresses that do not match expected subnets for the capture point. Internal addresses appearing on external-facing interfaces (or vice versa).
- **Fragmentation attacks**: Teardrop, Ping of Death, and similar attacks use malformed fragmentation. Look for overlapping fragment offsets or total reassembled sizes exceeding 65535 bytes.
- **Tunneling protocols**: GRE (Protocol 47), IP-in-IP (Protocol 4), and IPv6-in-IPv4 (Protocol 41) tunnels can bypass security controls. Unexpected tunneling traffic warrants investigation.

## Layer 4 Analysis Techniques

- **Port frequency analysis**: Generate a histogram of destination ports to identify unusual services. Commonly targeted ports include 445 (SMB), 3389 (RDP), 22 (SSH), 5985 (WinRM), and 135 (RPC).
- **Connection duration analysis**: Very short connections (under 1 second) followed by many more may indicate scanning. Very long connections to unusual destinations may indicate C2.
- **Bytes transferred per connection**: Calculate the ratio of bytes sent vs. received. Normal web browsing downloads more than it uploads. Reversed ratios may indicate exfiltration.
- **Source port analysis**: Scanning tools often use sequential or predictable source ports. Legitimate operating systems randomise ephemeral ports.

## Practical Tshark Commands for Protocol Analysis

- `tshark -r capture.pcap -Y "tcp.flags.syn==1 && tcp.flags.ack==0" -T fields -e ip.dst -e tcp.dstport | sort | uniq -c | sort -rn` lists SYN scan targets by frequency.
- `tshark -r capture.pcap -Y "dns" -T fields -e ip.src -e dns.qry.name` extracts all DNS queries with source IPs.
- `tshark -r capture.pcap -Y "icmp.type==8" -T fields -e ip.src -e ip.dst -e data.len` identifies ICMP echo requests with payload sizes.
- `tshark -r capture.pcap -qz conv,tcp` generates a conversation list showing bytes transferred per TCP session.
